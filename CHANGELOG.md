# Changelog

Все заметные изменения в проекте фиксируются в этом файле.

## [2.7.1] - 2026-10-09

### Fixed
- Карта регистров принимает ключи с префиксом типа регистра: декодер
  публикует input-регистры как `"input:30013"`, а db-writer понимал только
  числа и отбрасывал их с WARNING `bad addr key`. Из-за этого у датчиков
  yfm8/yts61 в `register_catalog` попадали только holding-регистры (5 из 19 и
  1 из 8), у input-регистров не было имён и единиц. Ключ разбирается в addr
  без префикса — так он приходит в decoded. Если input и holding дают один
  addr, остаётся первый, в лог — WARNING.

## [2.7.0] - 2026-10-09

### Added
- Учёт незаписанных пакетов: воркер фиксирует каждый пакет, который не удалось
  записать (после ретраев или сразу при ошибке данных) — время, топик, число
  попыток, причина. Хранится в памяти с момента запуска процесса.
  - `/health`: поле `failed_packets_total`.
  - `GET /health/failed`: счётчик и последние 50 пакетов (новые первыми).
  - Веб-интерфейс: секция «Незаписанные пакеты» со счётчиком в заголовке;
    вместе со статусом health обновляется раз в 30 с.

## [2.6.2] - 2026-10-09

### Fixed
- Пакет decoded больше не теряется целиком из-за 32-битного регистра.
  Столбец `raw` в `history`/`latest_state` — `INT`, а «нет данных» у `u32`
  (`0xFB000000…0xFFFFFFFF`) и большие значения `u32` в него не помещались:
  `asyncpg.DataError` откатывал весь пакет со всеми регистрами.
  - `na=true` → `value=NULL`, `raw=NULL` (прочерк в `latest_state`).
  - `raw` вне int4 → `raw=NULL`, значение остаётся в `value`; WARNING с
    `router/panel/addr` и значением, не чаще раза в час на регистр.
- Решение «писать ли в history» при `raw=NULL` с обеих сторон сравнивает
  `value` — иначе изменения такого регистра были видны только по heartbeat.
- In-memory состояние (периоды enum, биты неисправностей, gap-детектор, время
  последней записи) обновляется только после commit транзакции пакета. Раньше
  при сбое записи переход enum/fault терялся до следующей смены значения.
  Таймерный heartbeat тоже отмечает время записи только после вставки.
- Ошибка данных (`asyncpg.DataError`) больше не ретраится воркером (3 × 2 с
  впустую): пакет отбрасывается сразу, в логе — батч и `addr` регистра.

### Added
- `tests/test_decoded_write.py` — юнит-тесты записи decoded без MQTT/Postgres:
  `python -m unittest discover -s tests -t .`

## [2.6.0] - 2026-06-12

### Added
- Таймерный heartbeat (`heartbeat_flush_loop`): роутер не публикует регистр,
  пока его значение не меняется, поэтому событийный heartbeat не срабатывал и
  графики обрывались. Фоновая задача дописывает последнее известное значение
  аналоговых регистров живых панелей, по которым нет записей дольше
  `heartbeat_sec`. Настройки: `history_policy.heartbeat_scan_sec` (30),
  `history_policy.heartbeat_source_alive_sec` (120).

### Fixed
- Gzip-пакеты на `cg/v1/telemetry` (магия `1f 8b`) пропускаются молча: это
  сжатые регистровые дампы, их потребитель — декодер. db-writer берёт из
  telemetry только GPS, который приходит несжатым. Ранее каждый такой пакет
  давал UnicodeDecodeError с 3 ретраями воркера (~7500 ошибок в сутки).
- Неразбираемый payload (не-UTF-8, не-JSON, не-объект) больше не вызывает
  ретраи воркера с полным traceback — логируется одной строкой WARNING.
  Ретраи остаются только для временных ошибок (БД).

## [2.3.2] - 2026-05-18

### Added
- Поле `name` для KPI регистров в `config.yml` и веб-интерфейсе

## [2.3.1] - 2026-05-18

### Changed
- Дискретные/enum регистры (`state_events`): убран heartbeat — запись только при изменении значения. Gap detection на уровне оборудования через `data_gaps` делает heartbeat регистров избыточным.
- `enable_gps_reject_events: false` в `config.example.yml` — для стационарного оборудования GPS reject события не несут ценности.

## [1.1.0] - 2026-07-14

### Added
- многоуровневый ретеншн: таблицы `history_1min`, `history_1hour` для агрегатов
- фоновая задача агрегации (`src/aggregation.py`): raw → 1min → 1hour
- dirty-tracking для переагрегации опоздавших записей
- watermark-защита: retention не удаляет raw данные до их агрегации
- weighted average для часовых агрегатов (`SUM(avg*count)/SUM(count)`)
- per-register настройки через `kpi_registers`: `equip_type`, `min_interval_sec`
- SQL-миграция `schema/002_tiered_history.sql`

### Changed
- `min_interval_sec` по умолчанию: 10 → 2 сек
- retention: единый `history_days=30` → раздельный `history_raw_days=7` / `history_1min_days=30` / `history_1hour_days=365`
- `batch_size` по умолчанию: 5000 → 10000
- `kpi_map()` ключ: `addr` → `(equip_type, addr)`

## [1.0.0] - 2026-03-09

### Added
- HTTP `health` endpoint с состояниями `ok/degraded/dead`
- вывод версии сервиса в лог старта и `/health`
- `scripts/update.sh` для обновления установленного сервиса

### Changed
- установка сервиса переведена на `/opt/db-writer`
- рабочий конфиг перенесён в `/etc/db-writer/config.yml`
- усилено завершение процесса при падении критического task
- обновлены параметры burst-нагрузки в `config.example.yml`
