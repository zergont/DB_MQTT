# Changelog

Все заметные изменения в проекте фиксируются в этом файле.

## [2.8.1] - 2026-10-24

### Changed
- Первый кадр enum-регистра и маски неисправностей после разрыва связи
  пишется в `history` и без изменения. Раньше неизменное значение после
  связи было не видно: 24.10 по `history` нельзя было проверить, что маски
  40400–40430 вообще пришли (первая строка — только у изменившейся 40408,
  через 2 мин 51 с после остальных регистров).
  - Признак — последняя строка регистра в `history` раньше конца
    последнего разрыва панели; работает и после рестарта.
  - Периоды `enum_history`/`fault_history` не меняются, таймерного
    heartbeat для enum и масок по-прежнему нет.

## [2.8.0] - 2026-10-24

Разбор ДЭС №3 (1126246373/pcc/1) после обрыва 24.10 (связи не было
с 05:48:15 до 12:38:49 МСК).

### Fixed
- Таймерный heartbeat переносил значение через разрыв связи. Медленные
  записи роутер шлёт только при изменении, снимка после связи нет; heartbeat
  брал из `latest_state` значение, снятое до обрыва, и писал его со свежей
  меткой. 24.10 на стоящей машине рабочие значения (43010 = 33,6 %,
  40230 = 11,6 psi, 40247 = 27,3 В, 40258 = 265,7 psi) повторены в 12:38:59,
  12:54:07 и 13:09:08 — 27 строк одной транзакцией heartbeat.
  - Значение, снятое раньше конца последнего разрыва панели, heartbeat не
    повторяет, пока регистр не придёт заново.
  - Конец разрыва запоминается при его закрытии и восстанавливается при
    старте из `data_gaps` (`max(gap_end)`).
  - Ограничения по возрасту нет: давно не менявшееся значение без разрыва
    подтверждено пакетами панели, его heartbeat пишется как раньше.
- Пакет, пришедший после более свежих (запоздалый, `ts_status=late`, метка
  раньше последней), откатывал состояние: трекер разрывов уходил назад,
  переход enum/fault на его метке закрывал период раньше начала
  (`state_end`/`fault_end` < start). Теперь такой пакет пишется только в
  `history` (все регистры, на своей метке); `latest_state`, периоды
  enum/fault, трекер разрывов и время последней записи не меняются.
  Запоздалые пакеты по порядку (досылка буфера) обрабатываются как обычные.
- `latest_state` не откатывается к более старой метке (`WHERE` в upsert).
  Исключение — метка в строке впереди часов сервера больше чем на 2 мин:
  часы роутера убегали вперёд и вернулись, иначе срез замёрз бы.

### Changed
- Одиночная запоздалая пачка внутри обрыва больше не делит разрыв на два.
  24.10 застрявшая пачка с меткой 11:48:09 (дошла в 12:38:28) разбила обрыв
  на `data_gaps` 615 (05:48:15 → 11:48:09) и 616 (11:48:09 → 12:38:58).
  Если разрыв закрыла запоздалая пачка и следующий разрыв начинается на её
  же метке, он продлевает первый. Честная досылка буфера не сшивается: её
  пачки идут подряд, и разрыв закрывается не на последней из них.
  - db-writer читает `ts_status` из decoded (декодер telemetry2 ≥ 2.3.0).
    Без поля поведение прежнее.
  - Отключается `gap_detector.merge_across_late: false` (по умолчанию `true`).
- README: проверка decoded и heartbeat без удалённого столбца `write_reason`.

## [2.7.3] - 2026-10-23

### Fixed
- Gap-детектор терял разрыв, если сервис перезапускался, пока панель молчала:
  метка последнего пакета жила только в памяти, первый пакет после рестарта
  не с чем было сравнить, а первый интервал только задавал средний и разрывом
  не считался. ДЭС №3 13–14.10: рестарт (деплой) во время 8-часового обрыва —
  в `data_gaps` не попали ни обрыв, ни следующая 34-минутная дыра (дописаны
  вручную, id 613, 614).
  - `restore_gap_tracker` при старте восстанавливает по `history` последнюю
    метку пакета каждой панели и средний интервал (медиана интервалов между
    последними 51 метками за сутки, ~1 с на запрос). Панели, молчащие дольше
    суток, — метка из `restore_write_timestamps`.
  - Пока средний интервал неизвестен, разрывом считается пауза длиннее суток;
    среднее задаёт первый нормальный интервал (раньше — любой первый интервал,
    и обрыв раздувал порог).

## [2.7.2] - 2026-10-13

### Fixed
- Таймерный heartbeat писал в `history` последнее значение с меткой `now`
  сервера. Пакеты роутера доходят с задержкой 1–25 с, и на пуске heartbeat
  обгонял ещё не доставленное показание: между рабочими значениями появлялась
  точка «со стоянки» (обороты/давление масла 0). За 30 дней — 11 таких строк
  на трёх машинах, все сразу после пуска.
  - Метка heartbeat-строки — «устоявшаяся» метка пакетов панели (часы
    роутера): предыдущая отличная метка, до которой все пакеты уже записаны.
    Последнюю брать нельзя: блоки одного цикла опроса идут с одной меткой и
    доходят с разбросом.
  - «Протухание» считается по часам роутера; строка не пишется, если
    значение в `latest_state` снято позже метки.
  - Время heartbeat-строк учитывается отдельно от настоящих записей:
    синтетическая строка не глушит через `min_interval` следующее изменение.
- `min_interval`/событийный heartbeat считаются по часам роутера (`ts`
  пакета), а не по времени приёма: пачка, доставленная разом, больше не
  теряет изменения внутри себя. Метка раньше последней записи (часы роутера
  отскочили назад) не замораживает запись.
- `restore_write_timestamps` берёт `max(ts)` вместо `max(received_at)`.

## [2.7.1] - 2026-10-09

### Fixed
- Карта регистров принимает ключи с префиксом типа регистра: декодер
  публикует input-регистры как `"input:30013"`, а db-writer понимал только
  числа и отбрасывал их с WARNING `bad addr key`. Из-за этого у датчиков
  yfm8/yts61 в `register_catalog` попадали только holding-регистры (5 из 19 и
  1 из 8), у input-регистров не было имён и единиц. Ключ разбирается в addr
  без префикса — так он приходит в decoded. Если input и holding дают один
  addr, остаётся первый, в лог — WARNING.

## [2.7.0] - 2026-10-09

### Added
- Учёт незаписанных пакетов: воркер фиксирует каждый пакет, который не удалось
  записать (после ретраев или сразу при ошибке данных) — время, топик, число
  попыток, причина. Хранится в памяти с момента запуска процесса.
  - `/health`: поле `failed_packets_total`.
  - `GET /health/failed`: счётчик и последние 50 пакетов (новые первыми).
  - Веб-интерфейс: секция «Незаписанные пакеты» со счётчиком в заголовке;
    вместе со статусом health обновляется раз в 30 с.

## [2.6.2] - 2026-10-09

### Fixed
- Пакет decoded больше не теряется целиком из-за 32-битного регистра.
  Столбец `raw` в `history`/`latest_state` — `INT`, а «нет данных» у `u32`
  (`0xFB000000…0xFFFFFFFF`) и большие значения `u32` в него не помещались:
  `asyncpg.DataError` откатывал весь пакет со всеми регистрами.
  - `na=true` → `value=NULL`, `raw=NULL` (прочерк в `latest_state`).
  - `raw` вне int4 → `raw=NULL`, значение остаётся в `value`; WARNING с
    `router/panel/addr` и значением, не чаще раза в час на регистр.
- Решение «писать ли в history» при `raw=NULL` с обеих сторон сравнивает
  `value` — иначе изменения такого регистра были видны только по heartbeat.
- In-memory состояние (периоды enum, биты неисправностей, gap-детектор, время
  последней записи) обновляется только после commit транзакции пакета. Раньше
  при сбое записи переход enum/fault терялся до следующей смены значения.
  Таймерный heartbeat тоже отмечает время записи только после вставки.
- Ошибка данных (`asyncpg.DataError`) больше не ретраится воркером (3 × 2 с
  впустую): пакет отбрасывается сразу, в логе — батч и `addr` регистра.

### Added
- `tests/test_decoded_write.py` — юнит-тесты записи decoded без MQTT/Postgres:
  `python -m unittest discover -s tests -t .`

## [2.6.0] - 2026-06-12

### Added
- Таймерный heartbeat (`heartbeat_flush_loop`): роутер не публикует регистр,
  пока его значение не меняется, поэтому событийный heartbeat не срабатывал и
  графики обрывались. Фоновая задача дописывает последнее известное значение
  аналоговых регистров живых панелей, по которым нет записей дольше
  `heartbeat_sec`. Настройки: `history_policy.heartbeat_scan_sec` (30),
  `history_policy.heartbeat_source_alive_sec` (120).

### Fixed
- Gzip-пакеты на `cg/v1/telemetry` (магия `1f 8b`) пропускаются молча: это
  сжатые регистровые дампы, их потребитель — декодер. db-writer берёт из
  telemetry только GPS, который приходит несжатым. Ранее каждый такой пакет
  давал UnicodeDecodeError с 3 ретраями воркера (~7500 ошибок в сутки).
- Неразбираемый payload (не-UTF-8, не-JSON, не-объект) больше не вызывает
  ретраи воркера с полным traceback — логируется одной строкой WARNING.
  Ретраи остаются только для временных ошибок (БД).

## [1.1.0] - 2026-07-14

### Added
- многоуровневый ретеншн: таблицы `history_1min`, `history_1hour` для агрегатов
- фоновая задача агрегации (`src/aggregation.py`): raw → 1min → 1hour
- dirty-tracking для переагрегации опоздавших записей
- watermark-защита: retention не удаляет raw данные до их агрегации
- weighted average для часовых агрегатов (`SUM(avg*count)/SUM(count)`)
- per-register настройки через `kpi_registers`: `equip_type`, `min_interval_sec`
- SQL-миграция `schema/002_tiered_history.sql`

### Changed
- `min_interval_sec` по умолчанию: 10 → 2 сек
- retention: единый `history_days=30` → раздельный `history_raw_days=7` / `history_1min_days=30` / `history_1hour_days=365`
- `batch_size` по умолчанию: 5000 → 10000
- `kpi_map()` ключ: `addr` → `(equip_type, addr)`
